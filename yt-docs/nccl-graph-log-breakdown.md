**📝 讲解：**
NCCL 探测到的 **CPU → PCIe Switch → GPU/NIC** 物理树状结构。

**重要：这 208 行里，每个 Rank 打印的内容完全一样。**因为这段描述的是整台机器的物理结构（CPU、NUMA、PCIe 怎么连），对所有 8 张卡来说是同一个答案。`8 rank × 26 行/人 = 208 行`。跟后面的全连通性矩阵不同——矩阵是以每个 GPU 为视角看其他节点的距离。

**如何读：** 以 **NUMA node 为根**，列出它直连的设备（PCI）和跨接的其他 NUMA（SYS）：
- `=== System : maxBw 48.0 ... ===`：全局瓶颈带宽估算（PCIe Gen4 x16 = 48 GB/s）。
- `CPU/0-0 (1/1/4)`：Socket 0, NUMA Node 0，括号内是 `(core_count / package_id / numa_node_id)`。

**以 NUMA 0 为例：**
```
CPU/0-0 (1/1/4)
+ PCI[5000.0] - NIC/0-0         ← 直连网卡（上行链路）
+ PCI[48.0] - GPU/0-27000 (0)   ← NUMA 0 直连 GPU 0
+ PCI[48.0] - GPU/0-38000 (1)   ← NUMA 0 直连 GPU 1
+ SYS[40.0] - CPU/0-1           ← 跨 QPI/UPI 总线到 NUMA 1
+ SYS[40.0] - CPU/0-2           ← 跨 QPI/UPI 总线到 NUMA 2
+ SYS[40.0] - CPU/0-3           ← 跨 QPI/UPI 总线到 NUMA 3
```

**这里有个关键映射：busId → GPU ID（括号里的数字）**。这段日志建立了后续所有节都要用的对照表：
| busId | GPU ID (rank) | 归属 NUMA |
|-------|:---:|----------|
| `27000` | GPU 0 | NUMA 0 |
| `38000` | GPU 1 | NUMA 0 |
| `49000` | GPU 2 | NUMA 1 |
| `5a000` | GPU 3 | NUMA 1 |
| `98000` | GPU 4 | NUMA 2 |
| `a8000` | GPU 5 | NUMA 2 |
| `b8000` | GPU 6 | NUMA 2 |
| `c8000` | GPU 7 | NUMA 3 |

**链路类型对比：**
| 标记 | 带宽 | 含义 |
|------|------|------|
| `PCI[48.0]` | ~48 GB/s | PCIe x16 Gen4，**同 NUMA node 直连** |
| `SYS[40.0]` | ~40 GB/s | QPI/UPI 系统总线，**跨 NUMA node** |

**GPU → NUMA 归属结论：** RTX 5090 无 NVLink，全部是 PCIe 卡：
- **NUMA 0**: GPU 0, GPU 1（两两很近）
- **NUMA 1**: GPU 2, GPU 3（两两很近）
- **NUMA 2**: GPU 4, GPU 5, GPU 6（三张卡挤一个 NUMA，彼此也很近）
- **NUMA 3**: GPU 7（单独）

1. `GPU/0-27000 (0/5000.0/LOC)` —— 到自身（GPU 0），本地显存（虚拟高带宽）。

4. `GPU/0-c8000 (3/40.0/SYS)` —— **到 GPU 7**：同样跨 NUMA。

- `graphs 0.02~0.03s`：路径搜索——暴力递归尝试 Ring/Tree 排列，极快。
- `alloc 0.09s / bootstrap 0.06s`：内存分配 + Rank 间握手建立。

**8 个 rank 的总耗时都是 0.85s**——因为初始化是同步阻塞的，大家等最慢的那个。
